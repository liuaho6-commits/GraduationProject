# quant_backend 项目模块开发文档

## 1. 项目概述
`quant_backend` 是一个基于 Django 和 Django REST Framework (DRF) 构建的量化交易与回测系统后端。该系统涵盖了用户资产管理、股票行情数据获取与存储、模拟交易引擎、量化策略回测以及后台系统管理等核心业务流程。

---

## 2. 核心模块详解

### 2.1 用户模块 (`users`)
负责管理系统用户的基本信息、认证鉴权以及虚拟资产状态。
* **主要模型 (Models):**
  * `UserProfile`: 扩展了 Django 原生的 User 模型，包含用户的虚拟资金账户信息，如 `balance`（当前可用余额）、`initial_capital`（初始资金）、`last_market_value`（昨日市值）、`daily_profit`（今日收益）以及 `avatar`（用户头像）等字段。
* **核心功能:**
  * 用户注册、登录与 JWT 认证鉴权。
  * 用户个人信息的查询与修改。
  * 资金账户的实时监控与结算。

### 2.2 股票数据模块 (`stocks`)
负责维护整个系统的底层金融数据，包括股票基础信息和历史/实时行情数据。
* **主要模型 (Models):**
  * `StockBasicInfo`: 存储股票的基础信息（如代码、名称等）。
  * `StockData`: 存储股票的日线级别行情数据。
  * `StockMinuteData`: 存储股票的分钟级别高频行情数据。
* **自定义管理命令 (Management Commands):**
  * `download_real_3y.py`: 脚本工具，用于从外部数据源（如 Tushare/BaoStock）下载近 3 年的真实股票日线行情。
  * `init_minute_data.py`: 初始化或拉取分钟级别的行情数据。
  * `fill_mock_data.py`: 为开发和测试环境填充模拟行情数据的工具。

### 2.3 交易与模拟引擎模块 (`trade`)
系统的核心业务模块之一，负责处理模拟交易、订单撮合、策略选股以及系统时间流转。
* **主要文件与组件:**
  * `engine.py`: 核心撮合引擎，负责处理订单状态的流转（如委托、成交、撤单）。
  * `executor.py`: 订单执行器，负责根据当前行情实际计算滑点、手续费并更新用户资产。
  * `scheduler.py` & `tasks.py`: 定时任务调度器（可能基于 Celery 或 APScheduler），负责在特定的模拟时间点触发收盘结算、策略执行等定时逻辑。
  * `time_utils.py`: 时间控制工具。结合根目录下的 `mock_time.json`，用于在模拟盘中控制虚拟时间的流逝。
* **主要模型 (Models):**
  * `Strategy` / `StockPool`: 用户配置的量化策略及对应的目标股票池。
  * `Order`: 订单表，记录用户的买卖委托记录及状态。
  * `TradeRecord`: 成交流水表，记录具体的成交明细。
  * `SystemSettings`, `TimeFlowSettings`: 系统级的全局配置和时间流转控制配置。

### 2.4 回测模块 (`backtest`)
提供独立于模拟盘的历史数据回测环境，用于评估量化策略的有效性。
* **主要文件与组件:**
  * `engine.py`: 回测引擎。与模拟交易引擎不同，回测引擎需要快速遍历历史行情（如通过 Pandas/Spark 加速），批量生成买卖信号并统计净值曲线。
  * `models.py`: 存储回测任务的配置参数（起止时间、初始资金、策略参数）以及回测结果（如夏普比率、最大回撤、收益率曲线等）。
* **核心功能:**
  * 接收前端传递的策略参数并生成回测任务。
  * 调用行情数据进行历史复盘。
  * 返回标准化的量化回测绩效指标给前端展示。

### 2.5 后台管理模块 (`managers`)
面向系统管理员（Admin）的独立业务模块，主要用于系统运营和监控。
* **核心功能:**
  * `permissions.py`: 定义严格的管理员权限校验规则（RBAC）。
  * 系统全局参数配置（如交易费率、模拟盘时间倍速等）。
  * 所有用户、订单、以及系统运行状态的宏观监控接口。

## 3. 全局配置与入口

* **`settings.py`**: Django 全局配置文件，包含数据库连接、DRF 设置、跨域配置、定时任务配置等。
* **`urls.py`**: 全局主路由，将 API 请求分发到 `users`、`stocks`、`trade`、`backtest` 等各个子模块。
* **`mock_time.json`**: 持久化存储当前系统的模拟时间节点，供 `trade` 模块读取和更新。
* **`asgi.py` / `wsgi.py`**: 服务部署网关配置。其中 `asgi.py` 为后续引入 WebSocket（如实时行情推送、回测进度推送）提供了异步支持。
* **`package.json`**: 根目录存在的 Node.js 配置文件，可能用于配置前端构建命令、格式化工具（Prettier/ESLint）或某些 Node 侧的辅助脚本。

## 4. 开发规范建议
1. **数据交互**: 所有对外的接口均需通过各模块下的 `serializers.py` 进行数据校验与序列化，确保数据格式符合 RESTful 标准。
2. **时间处理**: 鉴于金融业务对时间的高度敏感，尤其是模拟盘存在“系统时间”和“真实时间”的差异，所有涉及时间的获取务必调用 `trade.time_utils` 中的统一接口，避免直接使用 `datetime.now()`。
3. **并发安全**: 订单撮合 (`trade/engine.py`) 与资金扣减 (`users`) 必须使用数据库事务 (Database Transactions) 或锁机制，防止高并发下的超卖或资金计算异常。
